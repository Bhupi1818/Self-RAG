# Evaluation

## Question
Does self-reflection improve answer quality enough to justify extra LLM calls?

## Test set (`eval/testset.json`)
- ~40 **answerable** questions generated by an LLM from random chunks (each with a reference answer).
- ~8 **unanswerable** questions that the corpus cannot answer (to test refusal).
- Regenerate with `python eval/generate_testset.py --n 40`, then **manually review and delete bad questions**.
  A hand-checked set of 30 beats an unchecked set of 100.

## Systems compared
1. **Baseline RAG**: retrieve top-k, generate once.
2. **Self-reflective RAG**: router, grader, verifier, rewrite loop.
Same retriever, same LLM, same k.

## Metrics
| Metric | Definition |
|---|---|
| correctness | Judge LLM compares answer to reference: 1.0 / 0.5 / 0.0 (refusal on answerable counts as 0) |
| faithfulness | Claim-level support ratio of the answer against the context actually used |
| refusal_acc | Share of unanswerable questions correctly refused |
| false_refusal | Share of answerable questions wrongly refused |
| avg_llm_calls | LLM requests per question (cost proxy) |
| avg_latency_s | Wall-clock seconds per question |

## Running
```bash
python eval/run_eval.py            # full set
python eval/run_eval.py --limit 10 # smoke test
```
Outputs `results/eval_results.json` (per-question rows) and `results/eval_table.md` (paste into README).

## Threats to validity (mention these in interviews)
- **Judge bias**: the same model family judges and answers. Set `JUDGE_MODEL` to a stronger/different model.
- **Self-verification overlap**: the pipeline's verifier and the faithfulness judge use the same prompt style, so
  faithfulness gains are partly by construction. Spot-check 10-15 answers by hand and report agreement.
- **Synthetic questions** are easier than real user questions (they mirror chunk wording).
- **Small n**: with ~50 questions, differences under ~8 points are noise. Report counts, not just percentages.
